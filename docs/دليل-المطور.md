# دليل المطور - نظام المركز الفرنسي

## التقنية والبنية

النظام تطبيق محلي يعمل على Windows. الواجهة مكتوبة بـ HTML وCSS وJavaScript، والخادم بـ Node.js. التخزين المقصود هو Excel، وليس قاعدة بيانات خارجية.

| الملف | المسؤولية |
| --- | --- |
| `server.js` | API، قراءة وكتابة Excel، توليد الأكواد، الحسابات، PDF وExcel exports |
| `public/index.html` | هيكل الصفحات والنوافذ والأزرار |
| `public/app.js` | منطق الواجهة، النماذج، التنقل، الاستدعاءات إلى API |
| `public/style.css` | التصميم، RTL، الجداول والنوافذ |
| `data/main data 2.xlsx` | بيانات التشغيل الفعلية |
| `installer/FrenchCenter.iss` | إعداد ملف التثبيت Inno Setup |
| `تشغيل النظام.bat` | تشغيل التطبيق محليًا |

## التشغيل للمطور

ثبت Node.js LTS ثم نفذ `npm install` مرة واحدة، وبعدها `npm start`. افتح `http://localhost:3210`. لتشغيل قاعدة بيانات تجريبية: عيّن متغير `GARAGE_DATA_FILE` لمسار ملف Excel تجريبي قبل التشغيل.

## بنية ملف Excel

أسماء الصفحات معرفة في أعلى `server.js`: بيانات العميل، قسم الزيارة، قسم المخزن، قسم الموردين، المصروفات، حركة المخزن، حركة الحسابات، والموظفين. العناوين معرفة أيضًا كمصفوفات `*_HEADERS`.

عند إضافة عمود: أضفه إلى `*_HEADERS`، ثم إلى القراءة داخل `readData()`، ثم إلى الحفظ في `saveData()`، ثم إلى الواجهة إن كان مطلوبًا. لا تغيّر ترتيب/اسم عنوان قائم دون خطة ترحيل للبيانات القديمة.

## أهم الدوال

- `readData()` يقرأ Excel ويحوّله لكائنات التطبيق.
- `saveData()` يعيد حفظ البيانات إلى الصفحات المطلوبة.
- `nextCode()` يولد الأكواد التلقائية C وV وM وS وE وA/T.
- `appendAccount()` يحسب رصيد المركز بعد كل حركة مالية.
- `paymentInfo()` يتعامل مع تقسيم المبلغ على أكثر من طريقة دفع.
- `inventoryMovementsWorkbook()` و`inventoryMovementsPdf()` تصدران تقارير حركة المخزن.
- `request()` في `public/app.js` هو مدخل الواجهة لكل API.

## إضافة وظيفة جديدة بأمان

1. أنشئ نسخة من Excel التجريبي، ولا تعمل على ملف تشغيل العميل.
2. أضف endpoint صغيرًا في `server.js` واختبره أولًا.
3. أضف عناصر الواجهة في `index.html`، المنطق في `app.js`، والشكل في `style.css`.
4. افحص الصياغة: `node --check server.js` و`node --check public/app.js`.
5. اختبر إضافة، بحث، وتصدير قبل الرفع.
6. اعمل commit واضح وارفعه إلى GitHub. لا تعدّل `main` مباشرة بدون نسخة احتياطية.

## تشخيص الأخطاء

- «ملف البيانات غير موجود»: راجع مسار `GARAGE_DATA_FILE` أو `data/main data 2.xlsx`.
- «المسار غير موجود»: endpoint المطلوب غير معرف أو الواجهة تطلب URL خطأ.
- فشل حفظ Excel: غالبًا الملف مفتوح في Excel أو يوجد خطأ في عنوان عمود.
- PDF فارغ/قديم: أغلق نسخة السيرفر القديمة وشغّل التطبيق من جديد؛ تأكد من إعادة تنزيل/بناء Setup بعد تغيير `server.js`.
- راجع نافذة التشغيل، فهي تعرض stack trace ورقم السطر في `server.js`.

## قواعد للحفاظ على النظام عند توسعه

- لا تضع منطقًا ماليًا جديدًا داخل الواجهة فقط؛ يجب أن يكون التحقق في الخادم أيضًا.
- احتفظ بالأكواد كمعرّفات ثابتة ولا تستخدم الاسم كمعرّف وحيد.
- اكتب migration عند تغيير Excel schema.
- افصل تقارير PDF/Excel في دوال مستقلة ولا تكرر نفس الحساب داخل أكثر من مكان.
- قبل أي تحديث منشور: backup لملف Excel، اختبار بيانات واقعية، ثم build للتثبيت.
